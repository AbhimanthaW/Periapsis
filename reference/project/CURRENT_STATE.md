# Return Window current state

**Periapsis · Evidence snapshot · 12 November 2026, Colombo**

**Verdict.** Periapsis has a working engineering baseline and two reproducible decision components. The documentation engine can allow or refuse a specific calculation using real Mars evidence, and the mission runtime can replan a bounded synthetic scenario. They are callable separately. The browser currently has an editor and Atlas, with no operational mission view or planning HTTP service. The primary demo direction is a less-documented Martian site, and no candidate in the supplied implementation is qualified for that role. **Ready for application integration. The integrated demo and submission are still open.**

### Synthetic replay results

The reserve is 15 s. For each valid option, margin equals remaining time minus reserve minus modeled duration. The completed task `survey-done` stayed in the result on all four runs.

| Fixture state | Direct return | Science action | Result |
| --- | --- | --- | --- |
| Baseline, 100 s left | 40 s, +45 s margin (reverse control 48 s) | 75 s, +10 s margin | `science-a` |
| Middle corridor closed, 100 s left | 60 s, +25 s margin | 95 s, −10 s margin | `direct_return` |
| Middle corridor closed, 70 s left | 60 s, −5 s margin | Withheld | `RETURN_OVER_RESERVE`, no recommendation |
| Both corridors closed, 100 s left | No path | Withheld | `NO_RETURN_ROUTE`, no recommendation |

The historical handoff discusses station dwell in minutes. The merged `stations.v1` wire schema and executable fixture use whole seconds in `dwell_s`. `synthetic-fixture-v1` is the build identifier. The actual pack ID is `rw-synthetic`. [Station schema](../../contracts/stations.v1.schema.json) · [Fixture](../../contracts/fixtures/synthetic-v1/site.json)

These are fixture controls on a 3×5 grid. They validate closure handling, direction, reserve arithmetic and science feasibility. They establish no real travel rate, hazard threshold or Marswalk safety claim. The archive checks validate a derived DTM window's identity and geometry. Independent science and release acceptance are still pending. The original prepared Jezero manifest came from the preserved browser archive. This audit rebuilt the window from USGS and used the committed manifest and sidecar pins. Keep both source lineages in any release that includes the fixture. ## Skeptical judging assessment

| Judge question | Current answer |
| --- | --- |
| Does it solve the challenge? | The intended layered crew workflow fits the brief. The existing browser shows regional research. It cannot yet show an evidence-constrained field decision. |
| Is NASA data essential? | The real elevation support and refusal depend on an MRO CTX-derived USGS DTM. MOLA adds global context. The synthetic routing arithmetic uses fixture data. The final real-site demo must combine relevant products from multiple NASA missions and show how at least one challenge-listed NASA resource affects the decision. |
| What is differentiated? | A crew can inspect why a requested calculation is withheld at the exact approach geometry and see which alternate action is still supported. NASA has demonstrated EVA task replanning, so the evidence-to-decision link must be live and obvious. [NASA precedent](https://ntrs.nasa.gov/citations/20240000165) |
| What could prevent progression? | A map with documentation colors and no changed decision, synthetic routes drawn on real geography, unsourced declarations about sparse coverage, or a browser workflow that fails offline. Eligibility is also open until the project maps to the official resource list and resolves the scope of the Local Lead's guidance for Global Awards. |
